# TikTok Plus

[English](README_en.md)

为 TikTok 网页版添加键盘快捷键、Google / 自定义 AI 评论翻译和翻译全部。

## 快捷键

### 播放控制

| 快捷键 | 功能 |
| --- | --- |
| `Space` | 暂停 / 播放当前视频 |
| `↑` / `↓` | 切换到上一个 / 下一个视频 |
| `←` / `→` | 后退 / 前进 5 秒 |
| `H` / `F` | 影院全屏（含右侧工具栏） |
| `Esc` | 退出全屏；快捷键面板打开时则关闭面板 |

### 互动

| 快捷键 | 功能 |
| --- | --- |
| `Z` | 点赞当前视频 |
| `X` | 打开评论区 |
| `C` | 收藏当前视频 |
| `V` | 复制当前页面标题和链接 |
| `B` | 开关弹幕（如果页面提供对应控件） |
| `R` | 标记为不感兴趣 |
| `G` | 关注作者 |

### 搜索与帮助

| 快捷键 | 功能 |
| --- | --- |
| `Shift + F` | 聚焦搜索框 |
| `Shift + ?` | 显示 / 隐藏快捷键面板 |

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 或 [Violentmonkey](https://violentmonkey.github.io/)。
2. 在脚本管理器中新建用户脚本，将 [`tiktok_plus.js`](tiktok_plus.js) 的全部内容粘贴进去并保存。
3. 打开或刷新 [TikTok 网页版](https://www.tiktok.com/)。

## 使用说明

- 脚本仅匹配 `https://www.tiktok.com/*`。
- 普通播放和影院全屏中的字幕均水平居中，保留站点原有的字幕框限宽。
- 多数快捷键在输入框等可编辑控件聚焦时会停用，以免干扰输入；`Esc`、`Shift + F` 和 `Shift + ?` 仍可触发。
- 互动操作依赖 TikTok 页面当前提供的控件；TikTok 更新页面后，个别快捷键可能需要适配。

### 影院全屏

- `H` / `F` 进入影院全屏：整页进入浏览器全屏，当前视频卡片与右侧互动工具栏一起居中排布在黑底上，再按一次或按 `Esc` 退出。
- 视频按原始比例完整显示：竖版视频左右、横版视频上下补黑边，不会拉伸变形或裁掉画面。窗口尺寸变化、视频切换后自动重新计算。
- 右侧工具栏（头像与关注、点赞、评论、收藏、分享、音乐）在全屏内可见可点，与页面上的按钮行为一致。
- 「⋯」菜单在全屏内正常可用：倍速、小窗播放、字幕、不感兴趣、举报都能打开并点击。此前仅把播放器卡片设为全屏，TikTok 的菜单弹层挂在该卡片之外，因此会「点了没反应」；现在改为整页全屏，弹层留在全屏范围内。
- 左下角视频信息和工具栏在停止操作约 2.4 秒后自动淡出，字幕在播放器底部水平居中并保持可见；鼠标移动、点击、滚轮或按键时立即恢复控件。以下情况不会自动隐藏：视频暂停、菜单已打开、快捷键面板打开、正在输入，或鼠标停留在信息区/工具栏上。
- 按 `X` 打开评论时，右侧评论栏在全屏内正常显示，播放器与工具栏会扣除其宽度重新居中；关闭评论后恢复居中。
- 页面原有的导航栏、侧边栏和推荐列表在全屏期间隐藏，退出后完全还原，不影响页面自身播放器。
- TikTok 目前把画面绘制在超分 canvas 层、并将 `<video>` 设为透明，脚本会在全屏期间改用视频层并按 `contain` 取景。
- 若浏览器拒绝全屏请求（例如未获得用户手势或站点策略限制），会退回点击页面自带的全屏控件；两者都不可用时提示 `Fullscreen not allowed`，不会静默失败，也不会残留全屏布局。

## 评论翻译

- 主评论和展开后的回复正文下方会出现“翻译”按钮；空评论、纯图片和纯表情不显示。
- 默认使用 Google 翻译为简体中文，也可在“翻译设置”中切换到自定义 AI；“查看原文” / “查看译文”可来回切换，同一视频及本地持久化缓存中的译文会复用，滚动导致节点替换或关闭重开评论区也无需重复请求。
- 评论标题旁的“翻译全部”会翻译已加载的主评论和展开回复，随后随滚动加载、手动展开回复继续翻译。不会主动滚动或展开全部回复；标题结构无法识别时，仅保留逐条翻译。
- “全部查看原文”恢复原文并停止自动翻译，再次开启复用缓存。逐条查看原文的选择会保留，直到手动查看译文或重新开启总开关。
- 总开关在当前视频内保留：关闭评论区暂停派发新评论任务，重开继续；切换视频或刷新页面后关闭总开关。已经完成的译文可从持久化缓存复用。
- 默认使用与 Forum Translator 相同的 Google Chrome 扩展风格接口：`/translate_a/t?client=dict-chrome-ex`。同一文本共享进行中的请求，最多 6 个并发请求，并设置页面级 60 次/分钟滚动配额（非 Google 官方配额）；长评论按最多 900 字符的 Unicode 安全分段翻译。手动翻译优先于批量任务，已加载评论随阅读自动处理。
- 译文保存在 Tampermonkey 本地存储，默认 30 天有效，最多 500 条、50 万译文字符；切换视频、刷新页面后相同内容无需重新请求。仅在翻译成功后缓存。
- 网络失败、超时及可重试的服务端错误最多额外重试 2 次；服务返回 429 时全局冷却（60 秒、120 秒、300 秒，优先遵守 Retry-After），连续受限暂停任务，需手动恢复；等待中的任务不主动重复请求。遇到长期限流不能保证自动恢复。
- 翻译失败时保留原文，点击“翻译失败，重试”手动重试。只翻译正文，用户名、图片和原有操作不受影响；诊断事件可在浏览器控制台用 `[TikTok Plus][translate]` 检索。
- 每次首次翻译或重试会将该条评论正文发送到所选服务：Google 使用 `translate.googleapis.com`，AI 使用设置中的 Base URL；开启“翻译全部”也会发送后续加载的正文。请求不携带 Cookie；AI 仅在配置 Key 时携带 Bearer 认证，不会在失败后自动改用其他服务。
- 使用的是 Google 免 Key 非正式接口，非 Google 官方支持的客户端 API，可能限流或失效；翻译质量及服务可用性没有保证，需要网络能够访问该域名。
- 更新已安装脚本时，保存新版本并刷新 TikTok 页面。脚本使用 `GM_xmlhttpRequest`、用户脚本本地存储及菜单接口；为支持任意自定义 AI 地址声明了 `@connect *`。若管理器提示连接许可，只需允许你实际配置的服务地址和 Google；无需选择允许所有域名。

### 自定义 AI

1. 点击评论标题旁的“翻译设置”，或在 Tampermonkey / Violentmonkey 脚本菜单中选择同名入口。
2. 将翻译服务切换为“自定义 AI”，填写 OpenAI 兼容的 Base URL，例如 `http://127.0.0.1:3425/v1`。地址包括 API 前缀，不要追加 `/models`、`/responses` 或 `/chat/completions`。
3. 按服务要求填写 API Key；本地免认证服务可留空。选择 Chat Completions 或 Responses 接口，点击“读取模型”并选择模型。
4. 选择思考等级并保存，再使用原有逐条翻译或“翻译全部”。打开设置本身不会联网；读取模型只请求 `/models`，不会验证翻译接口是否可用。

- 两种接口均使用非流式请求。Chat Completions 使用 `/chat/completions`，Responses 使用 `/responses`，并设置 `store: false`。AI 每条评论完整发送，不按 900 字符拆分；最多 2 并发，单次请求超时 120 秒，沿用页面级 60 次/分钟配额、手动优先及有限重试。
- 思考等级包括“服务默认”、`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。“服务默认”省略参数；`none` 明确请求不思考。Chat 使用 `reasoning_effort`，Responses 使用 `reasoning.effort`。支持范围由服务和模型决定；不支持时提示调整设置，不自动降低等级。较高等级可能增加耗时和费用。
- 配置保存在用户脚本存储中。Key 不会回填页面或写入日志；输入新值可替换，留空保留已保存值，“清除 Key”并保存可删除。修改 Base URL 会清空旧 Key，请为新地址重新输入。远程 HTTP 连接不加密，请优先使用 HTTPS。
- 保存不同配置会停止自动翻译、取消旧队列和在途请求并恢复原文，需要重新点击翻译。缓存按地址、接口、模型和思考等级隔离，沿用 30 天有效期及容量限制，切回原配置可复用对应缓存。
- 模型列表仅说明模型 ID 可见，不保证所选模型支持对应接口或思考等级。认证、参数、无效响应、拒绝及未完成的输出均保留原文；可悬停失败按钮查看原因并点击重试。

## 验证

用浏览器打开 [`tests/comment-translation.html`](tests/comment-translation.html)，自动运行翻译交互、快捷键与影院全屏回归检查。测试使用模拟响应，不向 Google 或 AI 服务发送请求；刷新页面可重新运行。影院全屏用例复刻了 TikTok 的真实结构（工具栏是媒体卡片的兄弟节点、菜单弹层挂在该卡片子树之外），并用 `document.elementFromPoint` 验证菜单项能被真实命中，而不只是 `.click()` 能触发。该测试不能替代 TikTok 实际页面及脚本管理器中的验收。
